## 2. Product goal and user job profile

Goal: collect as many **potentially relevant remote C#/.NET Backend vacancies available to a Ukraine-based candidate** as permitted, preserve **complete job description where accessible**, track source/query completeness, and produce an auditable shortlist with no silently missing jobs.

Target: **Strong Junior to Middle .NET Backend/C#**, remote from Ukraine. Prefer Ukrainian platforms/employers, then Russian-speaking employers outside RF, then international employers where English is mainly written rather than demanding B2 spoken interviews. No mandatory office/hybrid; avoid indiscriminate Senior/Lead ownership, mandatory WPF, deep SQL/T-SQL/PLSQL or heavyweight cloud expertise as core requirements.

Relevant stack: C#/.NET, ASP.NET Core Web API, EF Core, LINQ, SQL/PostgreSQL, Python, RabbitMQ, Docker, REST/TCP, fintech/broker/exchange APIs, algorithmic trading and AI/ML integration. Some skills are being reinforced; do NOT exaggerate commercial depth.

Philosophy: collect broadly, **filter only after saving raw source discovery**. A filter's exclusion is not proof that a vacancy is unavailable. New sources can fail and must not be reported as zero matching jobs.

## 3. Implemented architecture

- C# **.NET 10** console/worker, code under `src/JobRadar`; AngleSharp, Npgsql, PostgreSQL 16.
- xUnit tests under `tests/JobRadar.Tests`; GitHub Actions `.NET CI`, real source smoke checks, and Docker Compose integration.
- Container: `Dockerfile`, `compose.yaml`, `.env.example` with persistent PostgreSQL and reports volumes, worker running as non-root. **Only integration-tested in CI: no user-owned server/Windows installation has been deployed.**
- Scheduling in long-running process: 08:00 / 13:00 / 19:00 **Europe/Kyiv**, provided a running host and DB exist.
- DB tables include canonical `jobs`, `job_queries` (search provenance), `crawl_runs`, `fetch_errors`, `retry_runs`, and Jooble `api_request_budget`.
- Source/query reconciling, persisted failed-fetch backlog, cooldown and capped retries, coverage drift alarms, and immutable scan reports.
- `full_text_at` / `HasFullText` denote successful **parser capture**, not independently audited completeness of every provider description.

| Source | Discovery and full text | Verified status and critical caveat |
|---|---|---|
| **Robota.ua** | `api.rabota.ua/vacancy/search` JSON; descriptions from `api.robota.ua/companies/{id}/published-vacancies` | Real paging: 59 IDs/page, first 3 pages distinct for broad test query. Do not assert complete national coverage: API totals can drift or be inconsistent, RSS can be capped, and individual company feeds can be truncated. `QUERY_RECONCILED` applies to **one configured query**, not an entire website.

## 8. Recommended Phase 8 (continue implementing, not re-planning)

**First priority:** make the triage useful and safe on real collected data while monitoring false negatives.

1. **Ranking evidence/validation:** add fixture-based regression set from real public job descriptions (with non-sensitive synthetic paraphrases in repo). Test Ukrainian/Russian/English negation, 'hybrid cloud' false positive, 'remote team' vs remote job, 'remote only in country X', relocation, contractors outside Ukraine, B2 spoken vs written, mixed seniority. Add hard/soft constraints as explicit signals; do not silently exclude uncertain roles.
2. **Freshness:** implement provider-grounded activity/closed checks where publicly supported, keep UNKNOWN otherwise. Log last checked and source of status; missing ID in capped feed never proves closed.
3. **Collection coverage:** seek authorized deeper pagination beyond capped DOU/Djinni RSS, robust Robota company-detail fallback, cross-board dedupe, coverage by source and by search term. Do not bypass 403/anti-bot controls.
4. **Operational readiness:** consider PG DB-wide scan lease, container healthchecks, graceful shutdown, metrics, backups and first-run validation. Persistent crawling cannot exist until user deploys a running host/DB.
5. **Output usefulness:** possibly add redacted shortlist CSV/Markdown, job scoring breakdown, candidate source URL, and per-run delta (new/unread/changed) that could feed opt-in notifications later.

**Avoid:** automatically applying to jobs; claiming remote/active status verified from heuristics; spending Jooble quota without explicit credential/budget; committing secrets, scraped private data, or raw exported candidate corpora into public repo.
